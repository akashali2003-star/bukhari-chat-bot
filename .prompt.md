# Reusable Prompt Generator

Turn the observed task pattern into a reusable project prompt.

## Goal

Identify a repeated task the user is doing repeatedly in this workspace or conversation, then create a reusable custom prompt that makes that work easier to repeat.

## Required behavior

1. Review the project context, files, and recent conversation for recurring patterns.
2. Determine:
   - the underlying task being repeated,
   - any required inputs or context,
   - the expected output format or style,
   - any project constraints, conventions, tools, or security rules.
3. If the pattern is not clear enough, ask a brief clarifying question before drafting the final prompt.
4. Create a custom .prompt.md file that is specific, practical, and reusable.
5. Use a concise but complete structure:
   - a clear objective,
   - required inputs,
   - constraints and workflow,
   - expected output format,
   - a short example invocation.
6. Keep the prompt scoped to the workspace unless the task clearly needs a personal/global prompt.
7. Preserve project conventions and important guidance from AGENTS.md or similar repo instructions.

## Output requirements

The final result should include:

- a title and short description,
- YAML frontmatter with mode and description,
- a clear task statement,
- inputs and context requirements,
- constraints and style guidance,
- output expectations,
- example usage.

## Example format

```md
---
mode: agent
description: Describe the reusable task this prompt helps with.
---

# Task Name

Describe the task in 1-2 sentences.

## Inputs
- What the user provides
- Which files, folders, or selections are relevant
- Any required context or constraints

## Workflow
1. Inspect the relevant code or project context.
2. Apply the requested change or analysis.
3. Validate the result with the smallest relevant check.

## Output
- Summarize findings.
- Provide actionable code or documentation changes.
- Call out assumptions and risks.

## Example
Use this prompt when: ...
```

## Quality bar

- Keep it actionable, not generic.
- Prefer explicit instructions over vague guidance.
- Make the prompt easy to reuse in future sessions.
- Include enough constraints to avoid blind or unsafe execution.
- If there are security, validation, or project rules, encode them directly in the prompt.

## Final step

After drafting the prompt, briefly explain:
- what task it helps automate,
- how to invoke it,
- which related customizations would make sense next.
